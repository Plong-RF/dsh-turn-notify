# 01 · 设计

## 1. 需求

用户的原话归纳：

> Harness 每轮对话都要等很久，我把它放后台去做别的事。但它结束之后没有任何提示，我看不到。希望完成时在 Windows 屏幕右下角弹一个对话框，至少给我一个反馈——像 Codex、WorkBuddy 那样。

后来逐轮补充出这些硬要求：

1. 完成时要响一声（Windows 那种"嘣"）。
2. 卡片要**跟着 Harness 的个性化变**：换主题、切深浅、装第三方主题插件，卡片都要跟着变。
3. 鼠标悬停、点击要有反馈，但**不要廉价的发光**，也不要明显的缩放（会抖）。
4. 卡片要**贴着右下角任务栏**，不能浮在离边一段距离的地方。
5. 正文长的时候卡片要**能变高**。
6. 等待我确认/回答时也要提醒。

## 2. 约束

| 约束 | 影响 |
|---|---|
| Windows 10/11 + PowerShell 5.1 | 卡片只能用 WinForms/GDI+ 绘制 |
| 插件不能碰会话日志、不能进上下文 | 只能用只读事件 + 派生状态 |
| 界面主题只存在于浏览器 | 必须有一条 浏览器 → 宿主 的上报通道 |
| 插件应当无依赖、无构建 | 纯 JS + 一个 PowerShell 脚本 |
| 用户可能随时切换主题 | 颜色必须运行时读取，不能编译期固化 |

## 3. 架构

```
                    ┌─────────────────────────────┐
   浏览器 (client.js) │  读 theme token / 焦点 / 可见会话  │
                    └──────────────┬──────────────┘
                                   │ POST /turn-notify/state
                                   ▼
   宿主 (index.js)   ┌─────────────────────────────┐
                    │  state.theme / focused / sessionId │
                    │  ctx.on('session/event')          │
                    │  ctx.on('user-questions/request') │
                    └──────────────┬──────────────┘
                                   │ spawn(notify.ps1, base64 JSON)
                                   ▼
   子进程 (notify.ps1) ┌────────────────────────────┐
                    │ WinForms 窗口 + 逐像素透明层      │
                    │ GDI+ 绘制卡片 / 播放系统通知音     │
                    └────────────────────────────┘
```

**为什么分三段**：宿主能感知会话事件，但不知道主题；浏览器知道主题，但弹不出 Windows 窗口；只有独立进程能画出不抢焦点的置顶窗口。三段各司其职，边界清楚。

## 4. 关键决策

### 4.1 触发点：`turn/end`，不是 `agent/status`

| 方案 | 结论 |
|---|---|
| 轮询 `agent/status` | ✗ 官方实践明确说不要轮询状态，且拿不到结束原因 |
| `turn/end` 持久事件 | ✓ 自带 `reason`（completed/error/blocked/…）、自带 `time`，可算时长 |
| `agent/status` 变 idle | 只在"所有驱动停下"时触发，语义是"空闲"而非"这轮结束" |

去抖：`turn/end` 之后 800ms 内如果同会话又来 `turn/start`（你把新消息插进去了），取消这次提醒。

### 4.2 提示形式：自绘卡片，不是系统 toast

系统 toast 需要注册 AppUserModelID，用 PowerShell 的 AUMID 会出现"Windows PowerShell"署名和图标；而且外观不可控、可能被勿扰拦截。

自绘卡片代价是**不进通知中心**，但换来完全可控的外观、位置、时长、交互。对"我看一眼就知道结束了"这个目标，可控性更重要。

### 4.3 渲染：逐像素透明窗口，不是普通窗体

| 版本 | 问题 |
|---|---|
| v1：普通窗体 + Region 圆角 | 圆角有锯齿、没有投影、不能做任何透明度动画 |
| v2：叠加控件 + 悬停改底色 | 能用了，但"发光"很廉价，且不能做位移动画 |
| v3（当前）：32 位预乘 alpha 的 layered window | 真圆角、柔和投影、可以只改位置和 alpha 而不重采样文字 |

关键做法：**卡片内容渲染一次（2 倍超采样），之后每一帧只是把它按整数坐标贴到画布上**。整数坐标 + 不缩放 = 文字永远像素级清晰，不会因为动画而抖动。

### 4.4 主题：运行时读 token，不是两套写死配色

最初用 `label-primary / label-secondary / label-tertiary` 三个 token，结果正文是 `#859289` 这种极灰的次级色，在深色卡片上对比度只有 3:1，用户直接说"糊"。

现在按**角色**取色（全部运行时读 `getComputedStyle`）：

| 元素 | token | Everforest 深色 | Everforest 浅色 |
|---|---|---|---|
| 卡片底 | `--dsw-alias-bg-overlay` | `#434F55` | `#fcf8eb` |
| 描边 | `--dsw-alias-border-l1` | `#65736d99` | `#bec5b273` |
| 标题 | `state-error-primary` 与 `state-warn-primary` 按 50% 混合 | `#e19d80`（橘红） | `#EC7B29` |
| 正文 | `--dsw-alias-label-primary` | `#D3C6AA`（鹅黄） | `#5C6A72` |
| 脚注 | `--dsw-alias-label-secondary` | `#859289` | `#939F91` |
| 状态条 | `state-success/warn/error-primary` | 绿/黄/红 | 同左 |

标题那个橘红不是写死的十六进制，是**用当前主题自己的红和黄现场混合**出来的——换主题橘红跟着变。

描边色是 CSS 的 `#RRGGBBAA`，.NET 要 `#AARRGGBB`，渲染前要做字节翻转，并在 JS 侧先与卡片底色合成成不透明色。

### 4.5 不打扰：精确版

只看"窗口是否在前台"太粗——你在 Harness 里看别的会话时，照样不知道这条已经结束了。

做法：客户端注册一个零尺寸组件到 `conversation.composer.dock`（session 作用域，props 里带 `sessionId`），挂载时上报"我现在看着哪条会话"，卸载时上报 null。宿主弹窗前比对 `focused && visibleSessionId === 这条会话`，两个都成立才跳过。

### 4.6 动效：位移 + 淡入，不是缩放

缩放会让整张卡每一帧都重新采样，文字边缘落在不同亚像素上 → 看起来在抖。字体越大越明显。

Windows 11 通知、Slack、微信的做法都是滑入淡出，不缩放。所以：

- 出现：从下方 4px 浮起 + 淡入
- 悬停：上浮 2px（阴影留在原位 → 有抬起感）
- 点击：淡出关闭

### 4.7 声音

`%SystemRoot%\Media\Windows Notify System Generic.wav`（Win10/11 系统通知的原声），找不到时回退 `SystemSounds.Asterisk`。多条同时出现只响一次，避免连珠炮。

### 4.8 层级

`WS_EX_TOPMOST` 只在 `Shown` 时设一次是不够的——别的窗口（比如设置弹窗）被激活后可能压上来。所以每 700ms 用 `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)` 抢回一次，整张卡存活期间一直保持。

`WS_EX_NOACTIVATE` 保证不抢焦点；万一系统还是把前台给了它，`Shown` 里立刻 `SetForegroundWindow` 还给原来的窗口。

## 5. 生命周期

```
turn/end ──(800ms 去抖)──▶ 过滤(原因/子代理/时长/前台) ──▶ 读会话标题
   ──▶ 组装 {title, body, meta, accent, colors, seconds}
   ──▶ spawn powershell -File notify.ps1 -PayloadB64 <base64 JSON>
   ──▶ 渲染一次卡片 → 播放声音 → 淡入 → 停留 → 淡出 → 进程退出
```

等待提醒走另一条路：`user-questions/request` / `approval/request` 瀑布监听里，同步取 `this.id || request.agent.id` 作为会话 id，弹 20 秒的琥珀色卡；不阻塞、立刻 `return next()`。

## 6. 失败模式与兜底

| 情况 | 兜底 |
|---|---|
| 客户端没加载（没刷新页面） | 用内置深色板，功能照常 |
| 客户端从未上报过主题 | `FALLBACK_THEME` |
| `powershell.exe` 不在 | 打日志，不弹 |
| `UpdateLayeredWindow` 失败 | 抛错退出（不会留下幽灵窗口） |
| 同屏超过 `maxStack` 张 | 放弃新卡，不排队 |
| 卡片进程崩溃 | 槽位在 `exit` 时释放 |

### 7. 明确不做

- 不进 Windows 通知中心（自绘窗口的代价）
- 不做"点击跳到那条会话"（需要客户端导航能力，留到 v2）
- 不做非 Windows 平台
