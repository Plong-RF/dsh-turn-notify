# 02 · 开发日志

记录从"能不能做"到 v1.0 的十轮迭代。每轮：改了什么 / 为什么 / 怎么验证的。

---

## R1 · 摸清可用的东西

先把"Harness 里哪个信号代表这轮结束"查清楚，而不是先写界面。

**查到的**

| 能力 | 出处 |
|---|---|
| `turn/end` 持久事件，带 `reason`（completed/error/blocked/…） | `session/event` |
| 会话标题 | `sessionQuery.readTitle(sessionId)` |
| 回合开始时间（算时长） | `turn/start` 事件的 `time` |
| 主题快照（含 `colorScheme` / `fontFamilies` / `fontSizes`） | 客户端 `ctx.theme.getTheme()` |
| 宿主能否注册本地 HTTP 路由 | `webServer.register({kind:'exact', path, handler})` |

**结论**：宿主插件 + 浏览器半边 + PowerShell 子进程，三段式。

## R4 · 配色太灰

第一版正文用了 `label-secondary`（`#859289`），用户的原话是"正文是灰色，非常灰的那种颜色"。

**诊断**：正文不该用次级文字色，那是给小字脚注的，对比度只有 3:1 出头。

**修法**：按角色重新映射——标题取主题的"红 + 黄"混合成橘红，正文用 `label-primary`（鹅黄），脚注才降到 `label-secondary`。

**验证**：用 Everforest 真实的 `tokensFor()` 输出渲染对照图，确认 `#E19D80` / `#D3C6AA` 在 `#434F55` 上的对比度可读。

## R5 · 卡片太"长条"

380 宽 × 86 高，宽高比 4.6:1，看着像一条横带。

**修法**：宽度 380 → 340，内边距 12 → 9，行距 6 → 4。宽高比降到 4.1:1。

## R6 · 被压到 Harness 下面

用户："弹出来的时候在 Harness 的下面。"

**实测**：卡片 `topmost=True`，而且把 Harness 激活后，卡片坐标处最上层的窗口仍然是卡片——即"刚弹出时是对的"，问题出在**弹出之后**又被别的窗口改变过层级，而卡片只在 `Shown` 里置顶了一次。

**修法**：
1. 每 700ms 用 `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)` 复查并抢回层级；
2. 顺带发现一个更糟的 bug——卡片弹出会**抢走前台**（正在别的窗口打字会被吃键）。在 `Shown` 里检测 `GetForegroundWindow() == 自己` 就 `SetForegroundWindow(原来的窗口)` 还回去。

---

## R7 · 悬停/点击没有反馈

之前只有"点击即关闭"，没有悬停态，关闭又是瞬间的，视觉上等于"没反应"。

**修法**：悬停变亮 + 手型光标 + 暂停倒计时；按下变色，120ms 后再关。

---

## R8 · "发光太廉价" → 上缩放动画

用户："这个发光效果太廉价了……点击的时候一个放大或缩小，有一种纵深的效果。"

**做法**：整个渲染重写成逐像素透明窗口（`UpdateLayeredWindow` + 32 位预乘 alpha），这样才能做真正的缩放、真圆角、柔和投影。

代价：`UpdateLayeredWindow` 的窗口**用 BitBlt 截不到**——从这一轮起，截图再也看不到卡片了，只能靠用户的眼睛和进程内导出的帧。

---

## R9 · "缩放会抖" → 换成位移 + 淡入

用户："移动上去放大时，感觉有点颤抖。"

**原因**：缩放意味着每一帧都重新采样整张位图，文字边缘落在不同亚像素上 → 抖动。字体越大越明显。

**修法**：
1. 去掉缩放，改成"出现时从下方 4px 浮起 + 淡入 / 悬停上浮 2px / 点击淡出"；
2. 卡片内容**渲染一次**，之后每帧只按**整数坐标**贴图 —— 文字永不重采样，彻底不抖；
3. 顺带修掉"贴不到任务栏"：窗口定位改成按卡片本体算，而不是按带 20px 透明投影边距的窗口算。实测 `gap_right=8px, gap_bottom=8px`；
4. 悬停不再改动倒计时——之前悬停暂停 + 卡片正好在右下角，鼠标停那儿卡片就永远不消失。

## R11 · 重启后主题不再跟随（v1.0.1）

用户："我操作了 Harness 的变化，它却没有跟着变化。"

**定位**：插件 `fiberPhase = active`（装好了、在跑），但 `GET /turn-notify/state` 返回 **404** —— 浏览器→宿主那条上报路由根本没注册。

**根因**：`apply()` 里用 `ctx.get('webServer')` **一次性探测**，而在这个 Harness 实例里 webServer 尚未就绪，拿到空值后整块注册被 `if` 静默跳过。插件不报错，所以状态仍显示 active——这是最坑的一点：**失败得毫无痕迹**。

**修法**：

```js
// 之前：服务没就绪就悄悄跳过
const webServer = ctx.get('webServer')
if (webServer) ctx.effect(() => webServer.register({ ... }))

// 之后：等它就绪
ctx.inject(['webServer'], (scope) => {
  scope.effect(() => scope.webServer.register({ ... }))
})
```

**加固**（这次不只修，还让下次能被看见）：

1. 客户端改成**每 2 秒比对一次主题色值**，变了就上报——不再只依赖 `theme/change`（有些主题切换不触发该事件）
2. 宿主新增 `GET /turn-notify/state?probe=1`，直接返回当前缓存
3. 每次上报落盘到 `%TEMP%\dsh-turn-notify-state.json`，出问题时有据可查

**验证**：重启后 probe 返回 200，内容里是真实的 Everforest 色值（`card:#434f55`、`title:#e19d80`、`body:#d3c6aa`），普通 GET 恢复 405。

**教训**：可选服务一律用 `inject` / `ctx.inject`，不要"先看一眼有没有"。插件加载期的服务可用性和运行时不是一回事。

# 踩过的坑（给 v2 省时间）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | PowerShell 5.1 按 **ANSI** 读 `.ps1` | 脚本里有中文注释 → 整份解析失败，报的还是 `&` 保留字之类的怪错 | 脚本**纯 ASCII**，文案走 base64 JSON |
| 2 | `Start-Process -WindowStyle Hidden` | 窗口的第一次 `Show` 被 STARTUPINFO 的 `SW_HIDE` 吞掉，窗口存在但不可见 | 用 `CreateNoWindow`（Node 侧 `windowsHide: true`） |
| 3 | WinForms `BackColor` 不接受带 alpha 的颜色 | 设 `FromArgb(240,30,30)` 直接抛异常，窗口建不出来 | 半透明只走 `Form.Opacity` 或分层窗口 |
| 4 | **BitBlt 抓不到分层窗口** | 截图里永远没有卡片，误以为卡片没显示 | 进程内 `-DumpFrame` 导出真实帧 |
| 5 | 分层窗口淡出只缩 alpha | 预乘 alpha 下 RGB 仍然太亮，边缘发白 | `ColorMatrix` 四个通道一起缩 |
| 6 | PowerShell 里 `DrawImage` 重载会挑错 | 传 `RectangleF` 时被解析成 `Point[]` 重载并报错 | 用整数 `Rectangle` + 明确的重载签名 |
| 7 | `Get-Content` / `Set-Content` 往返 | PS 5.1 默认按 ANSI 读，UTF-8 中文被写成乱码，文件直接坏掉 | 只通过编辑工具改文件，不要用 shell 往返 |
| 8 | `Region` 做圆角 | 边缘全是锯齿 | 改逐像素透明窗口 |
| 9 | 主题给的描边色是 `#RRGGBBAA` | .NET 要 `#AARRGGBB`，直接喂会变成完全不透明 | 字节翻转 + 先与底色合成 |
| 10 | 叠放槽位 | 多个会话同时结束会重叠 | 槽位由宿主分配，子进程 `exit` 时释放 |
| 11 | 置顶只是一次性 | 弹窗后打开设置框会被压下去 | 700ms 复查抢回 |
| 12 | `WS_EX_NOACTIVATE` 仍可能拿到前台 | 打字被吃键 | `Shown` 里发现就还回去 |
| 13 | 可选服务用 `ctx.get()` 一次性探测 | 服务后启动时注册被静默跳过，插件仍显示 `active`，看不出异常 | 用 `ctx.inject(['webServer'], ...)` 等它就绪 |

# 验证手段

| 手段 | 能证明什么 |
|---|---|
| `GET/POST /turn-notify/state` 的 405/204 | 状态通道通了，且免鉴权 |
| `-DumpFrame` 导出帧 | 卡片渲染、配色、字体、自动高度是否正确（且能看到内容，绕开截图限制） |
| 枚举窗口 `GetWindowRect` | 位置是否贴边、尺寸是否随正文变化 |
| `GetForegroundWindow` 前后对比 | 是否抢焦点 |
| `WindowFromPoint` + `GetAncestor` | 指定坐标处最上层是不是卡片 |
| 进程 `WaitForExit` 计时 | 自动关闭是否准时 |
| 用户肉眼 | 动效手感、层级、声音——这些只有人能看到 |
